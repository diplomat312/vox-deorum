# AGENTS.md - OpenCode Harness

This package is the harness that lets OpenCode model sessions pilot a Civilization V seat. It owns the seat runtime: what the model is shown, what it is allowed to do, and what gets recorded while it plays.

Vox Deorum stays authoritative. OpenCode is the session layer that holds the conversation with a model and returns reasoning, tool calls, usage and cost. The rules of the game, the world facts and the effects of every action come from Vox, never from OpenCode.

## Hard Rules

- **Simulation never launches Civilization V.** Replay reads a recorded corpus. Tests read a synthetic scenario. Nothing in this package starts the game, attaches to a live session, or needs a running bridge.
- **Every game read and write goes through the existing Vox MCP tools and the bridge.** Do not add a second path to game state, a direct HTTP call, or a private Lua shortcut. If a capability is missing, extend the MCP server where it belongs.
- **Capturing reasoning and usage is a first-class requirement, not debugging.** The reasoning behind a decision, the calls it produced and the tokens, cache reads and cost it consumed are part of the result. Design the trace store for the questions later stages will ask, rather than bolting it on after.
- **Secrets, live sessions and raw recordings never get committed.** No API keys, no session ids from a live run, no harvested source transcripts, no corpus files pulled from another branch.

## Conventions

- **ESM**: Always use `.js` extensions in imports, even for `.ts` files (`"type": "module"`).
- **Winston logger only**: never `console.log/error/warn` in production code (it is fine in tests).
- **Tests live under `tests/mock`** and are the only tier. They must not touch the network and must not touch a game, so they run anywhere.
- **Comment everywhere**: every function needs a comment, and the config files carry comments where they explain a choice.
- **No new dependencies**: everything comes from the repository root. Keep this `package.json` free of `dependencies` and `devDependencies`.

## Layout

```
src/        seat runtime, world access and corpus loading
tests/mock/ the only test tier, in process and offline
corpus/     recorded game fixtures, regenerated by scripts/harvest-corpus.mjs
scripts/    corpus harvesting, run through git show rather than a checkout
```

The plan for this package, including the stage order and what each stage must be true at the end, lives in [docs/plans/opencode-harness/](../docs/plans/opencode-harness/).

## Build and Test

- `npm run build`: TypeScript compilation to `dist/`
- `npm run type-check`: type checking without emit
- `npm run lint`: ESLint checks
- `npm test`: the mock tier under `tests/mock`
- `npm run harvest`: regenerate the recorded corpus

## Common Pitfalls

1. Forgetting `.js` extensions in imports.
2. Writing a test that opens a socket, or one that assumes the game is running.
3. Adding a second route to game state instead of using the MCP tools.
4. Treating reasoning or usage as optional logging rather than recorded output.
5. Committing a harvested transcript, a corpus pulled from another branch, or a credential.
6. Adding a dependency to this package when the root already has it.
